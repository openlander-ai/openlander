## 핵심 전환

**AS-IS** (현재): 웹 = 모니터링 대시보드. 액션 버튼은 직접 API 호출.
**TO-BE**: 웹 = 대시보드 + 챗봇. 액션 버튼은 챗봇 명령어 입력.

---

## 왜 이렇게 바꾸나

### 문제: 버튼과 AI의 동작 불일치

```
버튼: map_domain("api.myapp.com") → DNS 등록 → 끝
AI:   "api.myapp.com 연결해줘" → DNS 등록 → NEXT_PUBLIC_API_URL 업데이트
      → 프론트 재배포 → CORS 확인 → 백엔드도 필요하면 재배포
```

같은 기능인데 AI가 하면 후속 작업까지 자동으로 챙김. 두 경로가 공존하면 버튼 사용자만 손해.

### 해결: 버튼 = AI 단축키

버튼 클릭 → 채팅창에 명령어 자동 입력 → AI가 전체 플로우 처리.

---

## 동작 모델

### API Key 있을 때

```
[Deploy 버튼] 클릭
    ↓
채팅창 열림 + "deploy myapp" 자동 입력
    ↓
AI: 레포 분석 → 서비스 감지 → DB 필요 → 생성 → 환경변수 주입 → 배포 → 모니터링
    ↓
유저: 실시간으로 AI가 뭘 하는지 봄 (신뢰 형성)
```

```
[Map Domain 버튼] 클릭
    ↓
채팅창: "map api.example.com to myapp"
    ↓
AI: DNS 등록 → 환경변수 업데이트 → 관련 프로젝트 재배포
```

### API Key 없을 때

```
[Deploy 버튼] 클릭
    ↓
기존과 동일: pipeline.redeploy() 직접 호출
```

제품이 API key 없이도 정상 동작. 키 등록은 "더 나은 경험"으로의 자연스러운 업그레이드 경로.

## 웹 UI 구성

### 대시보드 (API key 무관 — 항상 제공)

| 영역            | 기능                                |
| --------------- | ----------------------------------- |
| 프로젝트 목록   | 상태 표시, 필터/검색                |
| 프로젝트 상세   | 빌드 로그, 환경변수, 도메인, 서비스 |
| 배포 히스토리   | 빌드 기록, 롤백 이력                |
| 서비스 관리     | DB, Redis, RabbitMQ 등 상태         |
| 시스템 모니터링 | 디스크, 메모리, 컨테이너 상태       |

### 챗봇 (API key 있을 때만)

| 요소             | 설명                                  |
| ---------------- | ------------------------------------- |
| 채팅 패널        | 화면 우측 또는 하단 슬라이드          |
| 스트리밍 응답    | AI 응답 실시간 표시                   |
| 진행 상태        | 빌드 단계, 서비스 생성 등 시각적 표시 |
| 에러 진단        | 실패 시 자동 분석 + 복구 제안         |
| 명령어 자동 완성 | 자주 쓰는 패턴 제안                   |

### 버튼 동작 분기

```
if (apiKeyConfigured) {
  openChatPanel()
  prefillCommand("deploy myapp")
} else {
  directApiCall()  // 기존 동작 유지
}
```

## 버튼 → 명령어 매핑 (예시)

| 버튼               | 챗봇 명령어                     |
| ------------------ | ------------------------------- |
| Deploy             | `deploy {projectName}`          |
| Redeploy           | `redeploy {projectName}`        |
| Map Domain         | `map {domain} to {projectName}` |
| Share (Public URL) | `share {projectName}`           |
| Rollback           | `rollback {projectName}`        |
| Stop               | `stop {projectName}`            |
| Restart            | `restart {projectName}`         |

## 기존 AI UI 정리

### 제거 유지 (DEC-038)

- 인라인 AI 카드 7종 (RecoveryReportCard, PostmortemCard, SecretScanCard 등)
- Fix with AI 버튼
- AI Analysis 타임라인 그룹

### 신규 도입

- 챗봇 패널 (단일 AI 인터페이스)
- 버튼→챗봇 연결 로직

## 구현 스코프 (추후 상세 플랜 필요)

### Phase 1: 챗봇 기반 구축

- 채팅 패널 컴포넌트 (메시지 렌더링, 스트리밍)
- LLM API 연동 (API key 설정 UI)
- 기본 명령어 처리 (deploy, redeploy, stop, restart)

### Phase 2: 버튼-챗봇 연결

- 기존 액션 버튼에 분기 로직 추가
- 명령어 자동 입력 + 채팅 패널 자동 열기
- API key 미설정 시 기존 동작 유지

### Phase 3: UX 다듬기

- 명령어 자동 완성
- 진행 상태 시각화 (빌드 단계 표시)
- 에러 시 자동 진단 결과 인라인 표시
- 히스토리 (이전 대화 보기)

---

## 설계 원칙

1. **단일 경로** — 모든 액션은 궁극적으로 하나의 파이프라인(MCP 도구 체인)을 탄다
2. **옵셔널 AI** — API key 없어도 제품이 동작. AI는 "더 좋은 경험"이지 "필수"가 아님
3. **투명성** — AI가 뭘 하는지 유저가 실시간으로 봄 (블랙박스 아님)
4. **점진적 학습** — 버튼으로 시작 → AI가 뭘 하는지 봄 → 자연스럽게 직접 타이핑으로 전환
