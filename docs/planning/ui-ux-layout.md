# OpenLander TUI Layout Specification

## 개요

OpenLander TUI의 화면 레이아웃 및 패널 구성 기획서.
기능 개발 완료 후 UI/UX 개선 단계에서 적용한다.

**핵심 원칙:** 유저의 모드(모니터링/배포/디버깅)에 따라 필요한 정보가 다르다. 오른쪽 패널이 컨텍스트에 따라 자동 전환되는 적응형 레이아웃을 사용한다.

---

## 레이아웃 구조

2분할 (좌: Chat, 우: Status) + 오른쪽 패널 상하 분리(조건부).

터미널 3분할 가로는 컬럼이 너무 좁아지므로 채택하지 않는다.

```
┌─────────────────────────────┬──────────────────────────────┐
│         Chat (60%)          │        Status (40%)          │
│                             │                              │
│                             │  (컨텍스트에 따라 내용 변경)   │
│                             │                              │
├─────────────────────────────┤                              │
│ > _                         │                              │
├─────────────────────────────┴──────────────────────────────┤
│                      Status Bar                            │
└────────────────────────────────────────────────────────────┘
```

### 반응형 처리

- 120컬럼 이상: 60:40 분할
- 80~119컬럼: 65:35 분할, Status 섹션 내 라벨 축약 (예: `Memory` → `MEM`)
- 80컬럼 미만: Status 패널 숨김, 상태바에 핵심 수치만 표시. `Tab`으로 Status 전체화면 토글.
- 도메인 URL이 잘리는 경우: 말줄임표 처리 (예: `app.mysi...`)

## 3가지 모드

### 모드 1: 모니터링 (기본)

유저가 대부분의 시간을 보내는 모드. 전체 시스템 현황을 한눈에 보여준다.

```
┌─ Chat ─────────────────────┬─ Status ─────────────────────┐
│                             │ ▸ System                     │
│ You: 상태 보여줘             │   CPU ██░░░░░░ 12%           │
│                             │   MEM ████░░░░ 4.2/16GB      │
│ 4 projects running          │   DSK ██████░░ 72% (340GB)   │
│ CPU 12%, MEM 4.2GB          │                              │
│ No issues.                  │ ▸ Projects (4 running)       │
│                             │   ● frontend  :3000  128M    │
│                             │     app.mysite.com           │
│                             │   ● backend   :8080  256M    │
│                             │     api.mysite.com           │
│                             │   ● worker    :—     64M     │
│                             │   ○ demo      STOP           │
│                             │                              │
│                             │ ▸ Activity                   │
│                             │   14:32 dongbin ✅ frontend   │
│                             │   14:28 jihye   ✅ backend    │
│                             │   13:15 dongbin ❌ demo       │
│                             │                              │
│                             │ ▸ Alerts                     │
│                             │   ⚠ DSK 72% — cleanup 권장   │
│                             │   ⚠ demo 3주째 미접속        │
├─────────────────────────────┤                              │
│ > _                         │                              │
├─────────────────────────────┴──────────────────────────────┤
│ 4 projects │ CPU 12% MEM 4.2G │ Tab:패널 ?:도움말          │
└────────────────────────────────────────────────────────────┘
```

#### Status 패널 섹션 구성

**System (항상 표시)**

- CPU: 사용률 + 프로그레스 바
- MEM: 사용량/전체 + 프로그레스 바
- DSK: Docker 이미지/컨테이너가 쌓이면 디스크가 빠르게 차므로 반드시 표시

**Projects (항상 표시)**

- 상태 아이콘: `●` running, `◐` building, `○` stopped
- 포트, 메모리 사용량
- 도메인 URL (있으면 프로젝트명 아래에 표시)
- 키보드 `↑↓`로 프로젝트 선택 가능 (포커스가 Status 패널에 있을 때)

**Activity (항상 표시)**

- 최근 배포/변경 이력 (최대 5건)
- 타임스탬프 + 유저명 + 결과 + 프로젝트명
- 멀티유저 환경에서 "누가 뭘 했는지" 즉시 파악

**Alerts (조건부 표시, 이슈 있을 때만)**

- 능동적으로 문제를 알려주는 영역
- 최대 3건까지 표시. 초과 시 "N more — 전체 보기" 로 안내.
- 이슈 없으면 섹션 자체를 숨김 (공간 절약)
- 예시:
  - `⚠ DSK 85% — docker image prune 권장. 정리할까요?`
  - `⚠ demo 3주째 접속 없음. 중지하면 128MB 확보.`
  - `⚠ backend 24시간 내 3회 재시작`
  - `⚠ frontend 빌드 이미지 5개 누적 (2.1GB)`

### 모드 2: 배포 (빌드 시작 시 자동 전환)

빌드가 시작되면 Status 패널이 자동으로 상하 분할된다.

```
┌─ Chat ─────────────────────┬─ Status ─────────────────────┐
│                             │ ▸ System                     │
│ You: deploy my-frontend     │   CPU ████████ 89%           │
│                             │   MEM ██████░░ 8.1/16GB      │
│ 🔄 Deploying my-frontend... │                              │
│ 📦 Cloning... ✅ (2.1s)     │ ▸ Projects (4 running)       │
│ 🔨 Building... 67%          │   ◐ frontend  BUILD  67%    │
│                             │   ● backend   :8080  256M    │
│                             │   ● worker    :—     64M     │
│                             ├──────────────────────────────┤
│                             │ ▸ Build: frontend            │
│                             │                              │
│                             │ Clone ✅ → Build ◐ → Run ○   │
│                             │                → Expose ○    │
│                             │                              │
│                             │ Step 8/12: Installing deps   │
│                             │ ───────────────              │
│                             │ added 847 packages (34s)     │
│                             │ Building TypeScript...       │
│                             │ Compiling 142 files...       │
│                             │ ▏                            │
├─────────────────────────────┤                              │
│ > _                         │                              │
├─────────────────────────────┴──────────────────────────────┤
│ BUILD frontend 67% │ CPU 89% MEM 8.1G │ Ctrl+C:취소       │
└────────────────────────────────────────────────────────────┘
```

#### 동작 규칙

- 빌드 시작 → Status 패널 하단에 Build 패널 자동 등장
- Status 상단은 System + Projects (축소), 하단은 Build 패널
- 채팅에도 `[📋 Build panel opened]` 시스템 메시지 표시 (갑자기 바뀌면 혼란 방지)
- 빌드 완료 → 3초 후 자동으로 모니터링 모드 복귀 (또는 Enter로 즉시 닫기)
- 복수 빌드 동시 진행 시: 가장 최근 빌드 표시, `←→`로 빌드 간 전환

#### 파이프라인 시각화

한 줄 파이프라인으로 심플하게. 젠킨스처럼 복잡하게 하지 않는다.

```
진행 중:  Clone ✅ → Build ◐ → Run ○ → Expose ○
성공:     Clone ✅ → Build ✅ → Run ✅ → Expose ✅  (12s)
실패:     Clone ✅ → Build ❌
          Error: node-gyp rebuild failed
```

#### 빌드 로그 스크롤

- 기본: 자동 스크롤 (최신 로그 따라감)
- `↑↓` 입력 시: 자동 스크롤 일시 중지 (수동 모드)
- 수동 모드에서 `End` 또는 `f` 키: 자동 스크롤 재개
- 상태 표시: `[AUTO-SCROLL]` 또는 `[PAUSED — press f to follow]`

### 모드 3: 디버깅 (프로젝트 선택 시)

특정 프로젝트의 상세 정보 + 실시간 로그를 보여준다.

```
┌─ Chat ─────────────────────┬─ frontend ───────────────────┐
│                             │ ▸ Info                       │
│ You: frontend 로그 보여줘   │   Status:  ● running         │
│                             │   Port:    :3000              │
│ [최근 로그 50줄 표시]        │   Domain:  app.mysite.com    │
│                             │   Image:   sha256:a3f2...     │
│                             │   Uptime:  3d 14h             │
│                             │   CPU: 2%  MEM: 128M          │
│                             │   Last deploy: 2h ago         │
│                             │                               │
│                             │ ▸ Logs (live)                 │
│                             │                               │
│                             │ 14:32:01 GET /api/users 200   │
│                             │ 14:32:03 GET /api/posts 200   │
│                             │ 14:32:05 POST /api/auth 401   │
│                             │ 14:32:07 GET /health 200      │
│                             │ 14:32:09 GET /api/users 200   │
│                             │ ▏                             │
├─────────────────────────────┤                               │
│ > _                         │                               │
├─────────────────────────────┴───────────────────────────────┤
│ frontend ● :3000 │ CPU 2% MEM 128M │ Esc:돌아가기 r:재배포  │
└─────────────────────────────────────────────────────────────┘
```

#### 진입 방법 (2가지)

1. Status 패널에서 프로젝트 `↑↓` 선택 후 `Enter` (포커스가 Status에 있을 때)
2. Chat에서 자연어로 로그 요청 (예: "frontend 로그 보여줘")

두 방법 모두 동일한 디버깅 뷰로 진입한다.

#### 단축키

- `Esc`: 모니터링 모드로 복귀
- `r`: 해당 프로젝트 재배포
- `s`: 중지 (stop)
- `d`: 도메인 설정

#### 로그 스크롤

빌드 로그와 동일한 규칙 (자동 스크롤 + 수동 전환).

---

## 상태바 (하단, 항상 표시)

모든 모드에서 하단 1줄에 상태바를 표시한다. 모드에 따라 내용이 바뀐다.

```
모니터링: │ 4 projects │ CPU 12% MEM 4.2G │ Tab:패널 ?:도움말                 │
배포 중:  │ BUILD frontend 67% │ CPU 89% MEM 8.1G │ Ctrl+C:취소                │
디버깅:   │ frontend ● :3000 │ CPU 2% MEM 128M │ Esc:돌아가기 r:재배포 s:중지  │
```

**역할:**

- 현재 모드에서 가장 중요한 수치 요약
- 해당 모드에서 사용 가능한 키보드 단축키 표시
- "지금 뭘 할 수 있지?"를 매번 헤매지 않게 함

## 모드 전환 흐름

```
모니터링 (기본)
  │
  ├─ 빌드 시작 ──────────→ 배포 모드 (자동)
  │                            │
  │                            └─ 빌드 완료 → 모니터링 (자동, 3초 후)
  │
  ├─ 프로젝트 선택 (Enter) ─→ 디버깅 모드
  │                            │
  │                            └─ Esc → 모니터링
  │
  └─ "로그 보여줘" ──────────→ 디버깅 모드
                               │
                               └─ Esc → 모니터링
```

**전환 시 피드백:**

- 배포 모드 진입: 채팅에 `[📋 Build panel opened]` 시스템 메시지
- 배포 모드 복귀: 채팅에 `[📋 Build panel closed]` 시스템 메시지
- 디버깅 모드 진입/복귀: 시스템 메시지 불필요 (유저가 의도적으로 전환하므로)

## 패널 포커스 관리

`Tab` 키로 Chat ↔ Status 패널 간 포커스 전환.

```
Chat 포커스 (기본):
  - 텍스트 입력 가능
  - `/` 슬래시 명령 사용
  - ↑↓는 채팅 히스토리 스크롤

Status 포커스:
  - ↑↓로 프로젝트 선택
  - Enter로 디버깅 모드 진입
  - 텍스트 입력 불가 (입력하면 자동으로 Chat 포커스 전환)
```

**자동 포커스 복귀:**

- 키보드로 아무 문자 입력 시 → Chat 포커스로 자동 복귀
- 채팅으로 로그 요청하여 디버깅 진입 시 → Chat 포커스 유지
- Esc로 디버깅 모드 나올 때 → Chat 포커스로 복귀

## 데이터 갱신 주기

| 데이터               | 갱신 방식          | 주기   |
| -------------------- | ------------------ | ------ |
| System (CPU/MEM/DSK) | 폴링               | 5초    |
| Projects 목록/상태   | 폴링               | 3초    |
| Activity 로그        | eventBus 구독      | 실시간 |
| Alerts               | 폴링 + 분석        | 30초   |
| 빌드 로그            | NDJSON 스트림      | 실시간 |
| 런타임 로그 (디버깅) | docker logs 스트림 | 실시간 |

## Alerts 상세

Alerts는 OpenLander의 차별점. 단순 모니터링이 아니라 능동적으로 문제를 감지하고 해결책을 제안한다.

### 감지 항목 (v1.0)

| Alert                | 조건                                | 제안                          |
| -------------------- | ----------------------------------- | ----------------------------- |
| 디스크 부족          | DSK > 80%                           | 정리 실행 권장 (자연어)       |
| 미사용 프로젝트      | 2주 이상 요청 없음                  | 중지 시 확보 가능 메모리 표시 |
| 컨테이너 재시작 반복 | 24시간 내 3회 이상 재시작           | 로그 확인 권장                |
| 빌드 이미지 누적     | 프로젝트당 dangling 이미지 3개 이상 | 정리 시 확보 가능 용량 표시   |
| 포트 충돌            | 배포 시 포트 이미 사용 중           | 대체 포트 자동 제안           |

### 표시 규칙

- 최대 3건 표시, 심각도 순 정렬 (디스크 부족 > 재시작 반복 > 미사용)
- 3건 초과 시: "+N more — 전체 보기" 로 안내
- 이슈 없으면: Alerts 섹션 자체를 숨기고 Projects/Activity에 공간 할당
- 동일 Alert 반복 방지: 한 번 표시 후 dismiss하면 조건 재충족 전까지 미표시

## 구현 우선순위

### Phase 1: 기본 레이아웃

- [ ] 2분할 레이아웃 (Chat + Status)
- [ ] Status 패널: System + Projects 섹션
- [ ] 하단 상태바
- [ ] 반응형 컬럼 처리 (80/120 분기)

### Phase 2: 모드 전환

- [ ] 배포 모드 (Build 패널 자동 등장/소멸)
- [ ] 디버깅 모드 (프로젝트 상세 + 로그)
- [ ] Tab 포커스 전환
- [ ] 모드 전환 시 채팅 피드백 메시지

### Phase 3: 실시간 데이터

- [ ] System 리소스 폴링 (CPU/MEM/DSK)
- [ ] 빌드 로그 NDJSON 스트리밍 연결
- [ ] 런타임 로그 docker logs 스트리밍
- [ ] Activity 로그 eventBus 연결

### Phase 4: Alerts

- [ ] Alert 감지 로직 (데몬 측)
- [ ] Alert 표시 UI (Status 패널)
- [ ] 전체 Alert 목록 보기 (자연어 요청)
- [ ] 디스크 정리 기능 (자연어 요청)

## 참고: 기존 구현 현황

이미 존재하는 것 (재활용):

- `OpenLanderClient.deploy(repoUrl)` — IPC 배포 호출
- `client.streamBuildProgress(projectId)` — NDJSON 빌드 로그 스트림
- `client.listProjects()` — 프로젝트 목록 조회
- `eventBus` — deploy 이벤트 (start/clone/build/run/success/failed)
- `DashboardPanel` — 기존 대시보드 (리팩토링 대상)

새로 만들어야 하는 것:

- Status 패널 컴포넌트 (System/Projects/Activity/Alerts 섹션)
- 상태바 컴포넌트
- 디버깅 모드 뷰 (프로젝트 상세 + 로그)
- 포커스 관리 시스템 (Chat ↔ Status)
- Alert 감지 로직 (데몬 내 주기적 체크)
- System 리소스 수집 (os 모듈 or docker stats)
